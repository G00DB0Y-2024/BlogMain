# 图片居中修复历程

## 现象

`notes/01 推荐系统/推荐系统 (一).md` 中以独立 HTML 块形式插入的图片（如 `<img src="./assets/image-20260827104432043.png" alt="…" style="zoom:25%;" />`）在 `viewer.html` 中始终**靠左显示**，没有任何居中效果。其它以 Markdown `![]()` 形式插入的图片正常居中。

## 排查过程

### 第一轮：识别结构

通过 DevTools 控制台运行查询脚本，拿到 `<img>` 的父元素及 `<p>` 风格的判定信息：

```json
{
  "src": ".../image-20260827104432043.png",
  "parentTag": "ARTICLE",
  "parentClass": "",
  "siblingsCount": 202,
  "significantCount": 101,
  "pDisplay": "block",
  "pJustify": "normal",
  "pTextAlign": "start"
}
```

**结论**：这些 HTML 块 `<img>` 的父元素是 `<article id="write">`，**没有任何 `<p>` 包裹**。`centerStandaloneHtmlImages` 只在 `<p>` 上查找，因此根本没机会运行；既有的 `#write p.image-only` 选择器也匹配不到。

### 第二轮：分析根因

`viewer.html` 调用 `markdown-it` 时开启了 `html: true`。当 HTML 标签独占一行且前后均为空行时，`markdown-it` 把它识别为"HTML 块"，**不会**额外包一层 `<p>`，于是 `<img>` 直接成为 `<article>` 的子节点。

### 第三轮：定位祖先链与布局状态

```json
{
  "ancestors": ["IMG", "ARTICLE#write", "MAIN.viewer-content", "DIV.viewer-layout", "DIV.viewer-card", "DIV.viewer-shell"],
  "imgDisplay": "inline",
  "imgNaturalWidth": 972,
  "imgComplete": true,
  "parentDisplay": "block",
  "parentPaddingLeft": "37.5px",
  "articleWidth": 752.8
}
```

**结论**：`#write > img` 直接子级、`<article>` 宽度 752.8px、`img` 是行内元素 → 完全不会撑满容器居中。

## 修复过程

### 第一次尝试（无效）

在 `site.css` 中增加：

```css
#write > img:only-child {
  display: block;
  margin-left: auto;
  margin-right: auto;
}
```

**问题 1**：CSS 优先级被覆盖。`viewer.html` 加载顺序是 `site.css` → `inkwell.css`，而 `inkwell.css` 末尾的 `img { margin: 1em 0; }` 选择器特异性相同、后加载，覆盖了 `margin: 0 auto`。

**问题 2**：选择器过严——`:only-child` 要求 `<img>` 是 `<article>` 的唯一子元素，但实际文章里 `<article>` 有 200+ 直接子节点，**根本不匹配**。

**问题 3**：与既有约定不符。`site.css` 顶部注释明确说明「Markdown content styling lives in `./inkwell.css`」，把 `#write` 内的图片规则写在 `site.css` 违反了既定分层。

### 第二次调整（仍无效）

把规则迁移到 `inkwell.css` 的 `img` 块后面，但**保留了 `:only-child`**：

```css
#write > img:only-child {
  display: block;
  margin-left: auto;
  margin-right: auto;
}
```

**问题**：依然要求 `<img>` 是 `<article>` 唯一子元素，**没命中**。

### 第三次最终方案（生效）

去掉 `:only-child`，改为直接选择 `#write > img`，并同步更新 `site.css` 中的同名规则：

**`inkwell.css`（`/===== Images =====/` 块后追加）：**

```css
/* Standalone HTML images that markdown-it places directly under #write */
#write > img {
    display: block;
    margin-left: auto;
    margin-right: auto;
}
```

**`site.css`（`#write p.image-only > img` 规则块后追加）：**

```css
/* Standalone HTML images that markdown-it placed directly under #write */
#write > img {
  display: block;
  margin-left: auto;
  margin-right: auto;
}
```

`inkwell.css` 中加载靠后，规则真正生效。验证结果：

```json
{
  "display": "block",
  "marginLeft": "auto",
  "marginRight": "auto",
  "width": 235.5,
  "leftEdge": 273.4,
  "parentWidth": 752.8
}
```

图片成功水平居中。

## 影响范围

- 作用于 `<article id="write">` 的直接子级 `<img>`。
- 行内图片（被 `<p>` 包裹）**不受影响**：它们始终在 `<p>` 内部，由 `#write p.image-only` 规则负责。
- 不会影响列表 `<li>`、引用 `<blockquote>` 等块内的 `<img>`，因为它们不是 `<article>` 的直接子级。

## 关键经验

1. **图片居中失败 ≠ 规则不生效**，先在 DevTools 验证 `display` 和 `marginLeft/Right` 的 computed value 是否变化。
2. **CSS 加载顺序决定优先级**——本项目里 `site.css` 是骨架、`inkwell.css` 是文章样式；写 `#write` 内部规则必须放进 `inkwell.css`。
3. **`:only-child` 不适合流式文章容器**——`markdown-it` 输出的 HTML 块会与 `<h2>`/`<p>` 等并列存在于 `<article>` 下，`:only-child` 几乎不可能命中。
